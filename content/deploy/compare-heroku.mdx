# Faable Deploy vs Heroku

**Short answer:** Faable Deploy keeps what made Heroku great — push your code and it runs, with no servers to manage — and fixes what Heroku left behind. You get a **permanent free plan** (Heroku removed its free tier in 2022), a **fixed monthly fee per project** instead of a bill that grows dyno by dyno, a **built-in Web Application Firewall**, **[Faable Auth](../auth/get-started.md) in the same subscription**, and **100% European hosting with full GDPR data sovereignty**.

## Why teams move from Heroku to Faable

### Start free, and stay free while you build

Heroku retired its free dynos in November 2022; today the cheapest option is a shared pool of Eco hours that sleeps after 30 minutes, and anything that must stay up is a paid Basic dyno per process. On Faable, the [Free plan](pricing.mdx) is permanent and needs no credit card: up to 3 projects, an instance per project, 50 deployments a day, custom domains and 10 GB of egress a month — and an idle app wakes in a few seconds.

### One fee per project, not per dyno and per add-on

A typical Heroku app is a dyno per process plus add-ons for logging, authentication and security — each on its own line of the invoice. Faable charges a **fixed monthly fee per project, never per user**: Hobby at 15 €/month includes unlimited deployments, the full instance catalog, Dockerfile builds, 50 GB of egress and Faable Auth with unlimited monthly active users. Free and Hobby never bill per GB; only Pro meters egress beyond its 100 GB. See [Deploy pricing](pricing.mdx).

### Security and identity out of the box

Every app sits behind a [managed Web Application Firewall](security-waf.md) running the OWASP Core Rule Set, on every plan. When your app needs sign-in, [Faable Auth](../auth/get-started.md) is already there — hosted login, social and passwordless login, MFA, passkeys and machine-to-machine tokens — under the same account, the same bill and the same data-processing agreement.

### European by construction

Heroku is a Salesforce product: picking its EU region moves where your dynos run, not who operates them or which law reaches the data. Faable is a European company on European infrastructure — **hosting is 100% European with full GDPR data sovereignty**, and support on Hobby and Pro comes straight from the engineers who build the platform.

### Modern defaults

[HTTP/3](http3.md), [image optimization](images.md) and streaming responses work out of the box — LLM apps can stream for minutes, with only a 60-second limit to the first byte (see [Hosting AI agents in Europe](ai-agents.mdx)). The [Faable MCP server](../cli.md#mcp-server) lets your coding agent deploy, read build logs and fix a failing release from your editor.

## Moving a Heroku app to Faable

Most Heroku apps move without code changes, because the model is the same:

| On Heroku                                                        | On Faable                                                                                              |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `git push heroku main`                                           | Push to your GitHub repository — Faable builds every push to the deploy branch                         |
| Buildpacks (`package.json`, `requirements.txt`, `composer.json`) | The same manifests are detected automatically — see [What the Builder Expects](build-requirements.mdx) |
| `Procfile` `web:` process                                        | Your `start` script or framework entry point; a Dockerfile on Hobby and Pro                            |
| Config vars (`heroku config:set`)                                | [Environment variables](environment.mdx), per app                                                      |
| `PORT` environment variable                                      | Same — listen on the port Faable provides                                                              |
| Ephemeral dyno filesystem                                        | Same model — keep data in a database ([Databases](guides/databases.md))                                |
| Custom domains + ACM                                             | [Custom domains](domains/custom-domain.md) with free automatic SSL, on every plan                      |

If your app uses Heroku Postgres, point it at any managed Postgres — the [Databases guide](guides/databases.md) covers EU-hosted options like Neon that take minutes to set up.

## When Heroku might fit better

- You rely on **Heroku Postgres, Redis or Kafka** as first-party services from the same vendor, or on a specific add-on from its marketplace.
- You need **background worker dynos or the Heroku Scheduler**: a Faable app is woken by inbound HTTP, so a long-running worker with no traffic is not a fit today.
