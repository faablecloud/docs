# Faable Auth vs Authelia

**Short answer:** they solve different problems. [Authelia](https://www.authelia.com/) is a **self-hosted single sign-on portal** that sits next to a reverse proxy and puts a login gate in front of services that have no authentication of their own — the classic homelab and internal-tooling use case. Faable Auth is a **managed, multi-tenant OAuth 2.0 / OpenID Connect identity server** that your own application integrates with, so _your users_ sign up and log in to _your product_.

If you're protecting Grafana, Sonarr or an internal dashboard behind Traefik, Authelia is likely the better tool. If you're shipping a SaaS with its own user base, Authelia isn't designed for that.

> Authelia details checked against authelia.com and its roadmap in September 2026 (v4.39). Its OpenID Connect provider is still labelled **open beta**, and several items below are on its roadmap for v4.40.

## Login pages

Both products give you a hosted login you don't write — the difference is who hosts it and who it is for.

**Authelia's portal** covers password login (with a passkey button when enabled), the second-factor screen with a method picker, password reset by email, device registration, the OIDC consent screen, and a user settings page where people manage their 2FA devices. Branding is limited to a logo, a favicon, a theme (light, dark, grey, OLED or automatic) and translation overrides — it ships in more than 70 languages. A different layout or palette means forking its React frontend.

**Faable Auth's [hosted login](hosted-login.mdx)** adds what a product with its own users needs: **sign-up**, social buttons, an emailed code or link, a [passkey offer](login-experience.md#inviting-users-to-create-a-passkey) right after login, device activation for a CLI, and per-client differences in which methods appear and in what order. Your logo heads every screen; the language is English or Spanish. On Pro it runs on [your own domain](custom-domain.md), with the certificate handled for you.

## CLI and administration

The `authelia` binary is a toolbox for operators: validate the configuration, generate password hashes and keys, run storage migrations, rotate the encryption key, and import or export users' TOTP and WebAuthn devices. **It has no command to create or delete a user or set a password** — users live in LDAP or in the YAML file, which you edit (`authelia crypto hash generate` gives you the hash to paste in). An admin panel and user management are on Authelia's roadmap, not yet started.

[`faable auth`](../cli.md#faable-auth) manages the users themselves:

```bash
faable auth users list --suspended
faable auth users get user_abc123              # identities, last login and IP
faable auth users suspend user_abc123 -r "left the company"
faable auth logs list --user user_abc123 --since 2026-09-01
```

## When Faable Auth is the better fit

- **You're building a product with its own users.** Sign-up, email verification, password reset, social login and a user API come with it; Authelia expects users to already exist in LDAP or a config file.
- **You're multi-tenant.** Each Faable [account](what-is-a-multi-tenant-identity-server.mdx) is an isolated tenant with its own clients, users and signing keys. Authelia is one instance, one directory.
- **You don't want to run identity infrastructure.** No container, no Redis, no session store, no upgrade window, no database to back up.
- **Other apps need a full OIDC provider** — dynamic registration for MCP clients, token exchange for keyless CI, logout across applications.
- **You need European hosting** without operating the servers yourself.

## When Authelia might fit better

- **You're protecting self-hosted services behind a reverse proxy.** Forward auth with Traefik, nginx or Caddy is exactly what Authelia is for, and Faable Auth does not do it.
- **You want per-route access rules or Duo push.** Authelia has both; Faable Auth is an identity provider, not a reverse-proxy gate.
- **Everything must stay on your own hardware**, with no third party involved at any point.
- **Your user directory is already LDAP** and you want to keep it as the source of truth.

## Can they coexist?

Yes, and it's a reasonable setup: Authelia in front of your internal infrastructure, Faable Auth for the product your customers log into. They don't compete for the same requests.
